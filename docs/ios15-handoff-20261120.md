## 2. 原生文件访问：先做可判定的只读 A/B

- [ ] **复现第一个确定的错误。** 在实验提交上运行 `python3 tests/test_host_file_access_probe.py`。该测试在本地 Linux/iSH 能通过，macOS runner 却在 `src/ios/Diagnostics/HostFileAccessProbe.c` 报 `no member named 'st_mtimespec'` / `'st_ctimespec'`。核对测试的严格 POSIX 编译参数与 Darwin 头文件实际暴露的字段。验收是 macOS 与 Linux 都保留读前/读后身份和时间戳检查并通过测试，不是注释掉检查或改成跳过。
- [ ] **让正对照失败时停止。** `HostFileAccessProbeView.swift` 的 `measure()` 当前即使未读到本 App 的 `Info.plist`，仍调用样本探针。先修成“未运行样本”；复核 Darwin `errno` 的整数类型、Swift/C 编译开关和桥接头，再做真正的 Xcode type-check。之前的 Swift 语法解析不能代替编译。
- [ ] **核对构建和打包输入。** 在 `b8245e6` 的 `.github/workflows/ios15-m0-baseline.yml`，探针 App 编译排在原生依赖准备之前；探针写 `probe-dd`，常规打包读 `m1/DerivedData`。这两个问题是代码审阅发现的后续风险，不是第二次 CI 的首个报错。应让普通对照和 Minis Files 诊断包来自同一份启用只读页面的构建；核对各自 Bundle ID、最低系统、哈希，并确认两边都有同一个手动入口。正常发行配置仍不显示该入口。
- [ ] **获准后才做同机真机对照。** 两版各自从原生“设置 → 关于”读取自己的 `Info.plist`，再试读同一份预置、无隐私的固定样本 `OpenMinisPermissionProbe/sample-v1.txt`。不通过文件选择器给该样本额外授权；不扫描其他目录，不回显正文。记录构建标识、是否解锁、执行阶段、数字 errno，成功时记录样本 ID、大小和文件身份。不用 iSH shell 或外部 MCP 的结果替代 App 自己的读数。

| 两份正对照都通过时 | 可以得出的结论 |
|---|---|
| 普通版 `EACCES` / `EPERM`，实验版匹配同一份已知样本 | 只证明这条路径在本次环境中有读取差异，不证明可写、全盘可读或 root。 |
| 两版都可读 / 都拒绝 | 没有观察到区分；保留两份报告，不判通过。 |
| 目标缺失、`ENOENT`、样本被换、任一正对照失败 | 试次无效或结论不明。区分缺失和拒绝，先核验样本和环境。 |

用户的最终诉求包括写入；本轮证据**只覆盖只读探针的本地逻辑**。若之后确需验证写入，另定只含用户专用测试文件的创建、读回和清理方案，不碰已有文件。

## 3. root 诉求：与主 App 权限分开验收

用户希望保留“原生文件访问”和“受限管理操作”两个独立目标。**现状不是 Minis 已有 root。** 实验分支里有单独的诊断原型和本地夹具；没有交付设备包，没有 App 到特权服务的验收。外部 ios-mcp 的普通命令身份和它的个别管理操作也不是同一回事。上游 [ios-mcp 官方兼容表](https://github.com/witchan/ios-mcp/blob/62c4464f688c8f269419924b1a19c996de75f175/README.md) 已列 iOS 15；不要把另一项目 Apelin 的最低系统要求套用过来。

下一步先列出用户真正需要的**具体管理操作**，逐项判断是否可用用户授权目录或普通 API 完成。可先用不提权的模拟后端验收：默认关闭、一次授权只对应一次操作、拒绝/撤销不产生副作用、审计不记录文件正文。不提供任意命令或任意路径入口，不向模型、iSH 或 MCP 暴露特权执行。此项不应阻塞第 2 节，也不能借交接来装系统组件或重启设备。

## 4. 独立 UI 补丁：一次只验收这个输入框

- 截图中的粗灰圈来自 iOS 15 `TextEditor` 自带底色，再叠一层带内边距的圆角填充。补丁只改 `src/ios/Views/Chat/AIChatView/Sheets/SubAgentRunDetail.swift` 和 `scripts/test_ios15_attachment_grid.py`。iOS 15 保留一层底色和一物理像素描边；不动聊天主输入栏。
- 在**干净的 `ff1f00f`** 工作树对离线包中的补丁做 `git apply --check /path/to/subagent-field-ios15.patch`。需要验证候选时，在独立工作树应用后运行 `python3 scripts/test_ios15_attachment_grid.py`。历史结果：16/16 本地测试通过；重新加入第二层填充的负例会失败。尚无该补丁的 Xcode 出包或真机截图。
- 真机验收：深/浅色、空输入、输入至四行、显示键盘、发送后清空和收起焦点；发送箭头不能被挤出卡片。另一个现象不是同一个缺陷：“最新输出”取子代理上一次非空正文，工具计数单独更新；底栏 `4s` 取外层工具步骤，不是子任务总耗时。
